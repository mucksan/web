1. ウォッチの手段（ExpertFlyer を使わない自前運用）

🔴 前提：Google Flights では予約クラス（Z）を判定できない。

Google Flights の内部データを実際にデコードして確認した結果、1区間あたり保持しているのは
運航会社 / 便名 / 発着時刻 / 機材 / キャビン(business) / 価格 のみで、
Z・D・C・J といった予約クラスのフィールドが存在しない。
これは取得方法を変えても解決しない Google Flights 自体の仕様である。

手段 予約クラス(RBD) 費用 用途
ANA 予約確認ページ（§冒頭URL） — 無料 🔴 自分の予約16区間の生存・時刻変更。最も確実な一次情報。発券まで毎日1回

🔴 ITA Matrix による Z クラス判定（実証済み）

Google が所有する ITA Matrix には
routing language の bc=（booking class） 指定があり、予約クラス単位で絞り込める。
2026年9月4日に実際に対照実験して動作を確認した：

検索条件（UA / SFO→MEX / 10-29） 結果
Extension = f bc=Y 3便ヒット — 10:45発（UA1271）／13:14発／22:48発（UA412）
Extension = f bc=Z 🔴 No flights found

→ bc= フィルタは確かに機能しており、10/29 の UA 全便で Z は開いていない。
Google Flights が「UA412にビジネスあり」と表示したのは Z ではなく上位バケット（J/C/D）だった。
窓口が UA1271 をエコノミーで取った理由がこれで裏付けられる。

🔴 使い方の訂正（2026/9/4 実測）

URLを開くだけでは検索が走らない。base64 URL は検索条件を復元するだけでクエリを発火しない。
実際に開いたまま 145秒待っても進捗バーが回り続け、結果が出なかった（SFO→MEX / GRU→LIS の両方で再現）。

正しい手順は3ステップ：

  1. python flightwatch.py matrix が生成するURLを開く（フォームに全条件が復元される）
  2. 「Modify search」タブをクリック
  3. 「Search」ボタンをクリック → ページタイトルが区間名（例 SFO ⭢ MEX）に変われば発火成功

完了までさらに 40〜90秒。完了すると URL に solution.sessionId が付く。

⚠️ 従来この項に「リンクをクリックするだけでよい」と書いていたが誤りだった。
上の bc=Y/bc=Z 対照実験はフォーム操作で行っており、URL直叩きは未検証のまま記載していた。

⚠️ Matrix の限界（正直な注意書き）

bc=Z が空振りしても、原因は2通りありうる：

  1. Z の座席在庫が無い（＝知りたかったこと）
  2. その市場に Z で発券される運賃が設定されていない（＝在庫と無関係）

Matrix は「運賃 × 在庫」を同時に見るため、この2つを分離できない。
ExpertFlyer は運賃と無関係に素の在庫（Z4 Z0 等）を表示するので、そこだけが本質的な差。
したがって Matrix が「無し」でも、確定判断は必ず ANA 窓口で行うこと。

3. 自前ツール tools/flightwatch

pip install fast-flights
cd tools/flightwatch

python flightwatch.py schedule   # 予約済み15区間のダイヤ・機材ドリフト検出
python flightwatch.py watch      # ウォッチ対象のビジネス空席（キャビン単位）
python flightwatch.py matrix     # Zクラス確認用 ITA Matrix リンクを生成
  • 結果は reports/latest_<mode>.md に出力。前回との差分（新規/消滅/時刻変更/機材変更/価格）を自動表示
  • HIT または ダイヤ変更があれば終了コード2を返すため、タスクスケジューラから拾える
  • 設定は watchlist.json（監視対象・判定ルール・RBD前提）
  • 詳細は tools/flightwatch/README.md

4. 実行方法：Cowork の「このコンピュータを必須にする」を使う

🔴 判断の分岐点は、スケジュールタスク作成画面の一番下にあるトグル1つ。

このコンピュータ（leira）を必須にする
お使いのコンピュータが起動しているときのみ実行されます。
このコンピュータで許可したフォルダおよび Claude in Chrome へのアクセスが可能になります。

トグル 使えるもの 制約 登録するタスク
🔴 オン（推奨） ローカルファイル ＋ 自分のChrome PCが起動中のときだけ実行 タスクL（実取得）＋タスクB
オフ 実質ネットワークなし（下表） PCの電源に依存しない タスクR（リマインダーのみ）

オンにすれば、9/4 に実測した遮断はすべて回避できる。
Claude in Chrome は利用者自身のChromeを操作するため、Coworkのプロキシを通らない。

トグル「オフ」で実測した遮断（2026/9/4）

遮断された箇所 実際に起きたこと
matrix.itasoftware.com プロキシが即座に 403（許可リスト外ドメイン扱い）
google.com/travel/flights provenance（出所確認）承認待ちでタイムアウト。無人実行なので承認者がいない
WebFetch の性質 JSを実行しない一回限りのHTML取得。Matrixは描画に40〜90秒かかるため、通ってもスケルトンHTMLしか取れない
ブラウザ操作 クラウドの隔離セッションにデスクトップブリッジが無い

6. 🔴 ウォッチしても意味が薄いもの（時間を使わない）

対象 理由
欧州域内4区間の座席品質 中央席ブロックのリクライニングで各社横並び。1〜2時間の飛行で差が出ない（C-2）

LIM⇢GRU の地上区間を飛行区間に戻すこと 同上。かつイグアス3泊の行程が崩壊する
